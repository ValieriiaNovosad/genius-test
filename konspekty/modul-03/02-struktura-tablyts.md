# 3.3–3.4. Структура таблиць, ключі, нормалізація

> Модуль 3 · теорія схеми + огляд employees

---

## Головна ідея

Таблиця в БД строгіша за Excel: назва, типи стовпців, правила цілісності. Розуміння **ключів і зв’язків** = основа для JOIN пізніше.

---

## Елементи таблиці

- Рядок = один об’єкт (працівник, зарплата…).  
- Стовпець = характеристика з **типом даних**.  
- Кожна таблиця має ім’я в схемі.

### Ключі (види)

| Ключ | Сенс |
|------|------|
| Primary Key (PK) | Унікально ідентифікує рядок |
| Foreign Key (FK) | Посилання на PK іншої таблиці |
| Candidate / Unique | Кандидати на унікальність |
| Composite | Ключ з кількох стовпців |

### Нормалізація (інтуїція)

Рознести дані по таблицях, щоб не дублювати (окремо люди, окремо зарплати, окремо відділи) — менше аномалій оновлення, чіткіші зв’язки.

Типи зв’язків: **1:1**, **1:N**, **N:M** (часто через таблицю-міст).

---

## 3.4. Практика: схема employees

У Workbench:

1. Підключитись до сервера.  
2. Переглянути таблиці в Navigator.  
3. **Database → Reverse Engineering** → обрати `employees` → отримати ER-діаграму сутностей і зв’язків.

Мета: «побачити» модель очима, перш ніж писати JOIN.
